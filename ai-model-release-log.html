What “release” means here

A date register is useful only if the convention is stable. This page records the earliest date the lab says the named artifact became usable by its stated audience.

DATE RESOLUTION PROTOCOL

  1. GA / release: use the announcement date when access begins that day.
  2. Preview: include only when named users can actually access it; stamp PREVIEW or LIMITED.
  3. API after app: keep the first release row and state the later API date in availability.
  4. Checkpoint variants: separate rows only when the lab explicitly releases separate artifacts.
  5. Redeployment: availability changes belong in status notes, not as a second model launch.

AMBIGUITIES TO PRESERVE

Preview versus GA

A preview is not silently upgraded to GA. DeepSeek V4 Pro therefore has a preview row and a later GA row; the state transition is the useful fact.

Staged and region-limited access

The date is the first documented access date, with the restriction written in the status/API cells. It does not imply universal availability.

Silent model swaps

A behavior change behind an unchanged name is excluded unless the lab gives it a dated release identity. Product release notes alone do not create a row.

Version lineages

Square = general release, circle = preview/controlled, filled = open-weight artifact. Published retirement dates are shown; no date means the lab had not published one by the verification cutoff.

Common mistakes / anti-patterns

How release histories become wrong even when every link is real.

ANNOUNCED ≠ USABLE

Record a preview only when the announcement names an audience with access. A roadmap promise does not get a row.

FAMILY ≠ ENDPOINT

A family post can name several artifacts. Keep the exact model/version and access channel, not a vague family label.

CURRENT PRICE ≠ LAUNCH PRICE

This table preserves checked headline pricing. Follow the official pricing page before budgeting; rates and discounts drift.

Coverage and method

The register is designed to be maintainable: narrow inclusion, source-first updates, explicit unknowns, and a visible cutoff.

Tracked labs

  • OpenAI, Anthropic, Google DeepMind / Google, Meta
  • Mistral, DeepSeek, Alibaba Qwen
  • Other frontier or near-frontier trainers enter when a qualifying primary announcement is found

Announced releases are structurally overrepresented; silent swaps and labs without public release notes are underrepresented.

Update protocol

  • Check official lab news, model cards, API release notes and pricing docs weekly.
  • Cap a routine update at 10 new rows; on anomalous dates or conflicting sources, change nothing and report.
  • Never revise an existing date without preserving and comparing the source evidence.
  • Report omissions via GitHub Issues with the lab’s announcement URL.
