# Runbook: host a built multi-file project on the cheatsheets site

Use this to fold a project with its own repo and build (Vite/TypeScript app, WebGL toy, data viz with assets) into `cheatsheets.davidveksler.com`. Design and rationale: [`specs/apps.md`](specs/apps.md). Worked example: `black-hole-flight-simulator` from `~/Projects/m87-descent`.

**Shape:** source and tests stay in the project repo. CheatSheets vendors the build: the entry page at the root as `<slug>.html` (so catalog, hubs, sitemap, popularity and the SEO gate pick it up like any sheet), and assets under `apps/<slug>/`. `scripts/sync_app.py` copies the build over and `scripts/check_apps.py` gates it.

## 0. Is it an app?

| Situation | Do this |
|---|---|
| Fits in one self-contained `.html` (inline JS/CSS, small data) | A normal sheet ([`content.md`](content.md)). Not this runbook. |
| Needs a bundler, npm deps, binary assets (audio, models, LUTs), or a test/QA suite | This runbook. |
| Needs a server (API, DB, auth) | Not this. Use a Worker or the droplet, and link to it from a sheet. |

Pick the slug for search, not the repo name. It becomes the public URL `/<slug>.html` and renaming later costs a redirect. Example: `black-hole-flight-simulator`, not `m87-descent`.

## 1. Prepare the source repo

1. **Base path from the environment.** The build must accept `APP_BASE` (always `/apps/<slug>/`). Vite:
   ```ts
   // vite.config.ts
   import {defineConfig} from 'vite';
   export default defineConfig({base: process.env.APP_BASE ?? '/'});
   ```
   Other bundlers: the equivalent public-path option (webpack `output.publicPath`, esbuild `--public-path`).
2. **No root-absolute runtime URLs.** Find them: `grep -rnE "['\"\`]/[a-z]" src`. Rewrite every `fetch('/x.json')`, `new Audio('/a.mp3')` and worker or model URL to `` `${import.meta.env.BASE_URL}x.json` ``. Vite rewrites HTML and CSS references itself.
3. **Namespace browser storage.** Prefix `localStorage`/IndexedDB keys with the slug: every app shares one origin with 200+ sheets.
4. **QA under the base.** The QA harness must open `http://127.0.0.1:<port>${APP_BASE}`. `vite preview` serves only the base path, so a missed absolute URL then fails QA instead of production. Watch for `${url}/#hash` concatenations, which turn into `//`.
5. **Head = the cheatsheets metadata contract** (AGENTS.md template), written in the source `index.html` because the sync copies it verbatim:
   - `<title>` ≤ 60 chars, search phrase first; meta description 150–200; meta keywords
   - canonical `https://cheatsheets.davidveksler.com/<slug>.html`
   - OG + Twitter with absolute URLs; `og:image` = `https://cheatsheets.davidveksler.com/images/<slug>.png`
   - JSON-LD `@graph`: `WebApplication` (author `@id` `https://davidveksler.com/#person`, `creditText`, publisher, `datePublished`, `isAccessibleForFree`, `browserRequirements`), `BreadcrumbList` (Cheatsheets → hub → page), and `FAQPage` only if the FAQ is visible on the page
6. **Crawlable substance.** Immersive apps render almost no text. Add:
   - one keyword H1 (it can be styled as an eyebrow);
   - an About/help panel that's in the HTML, not generated by JS, with sourced key numbers and an FAQ;
   - a `<noscript>` summary;
   - links back to the related sheet, its hub and `/`.

   Facts follow the provenance rules: a source URL for each external figure, and derived figures marked as derived.
7. **Drop host-only files** (`public/robots.txt`, `sitemap.xml`, `llms.txt`): the site has its own. If the repo must keep them, list them in `drop` instead.
8. **Retire the repo's own deploy.** Make `scripts/deploy-*` refuse with a pointer to this runbook. Rewrite `docs/deployment.md` and AGENTS.md to say releases go through CheatSheets. Point any live-verify script at the new URL.
9. Update the repo's own SEO gate so it asserts the cheatsheets canonical. Then run its check with the base set:
   ```bash
   MSYS2_ENV_CONV_EXCL=APP_BASE APP_BASE=/apps/<slug>/ npm run check
   ```
   (`MSYS2_ENV_CONV_EXCL` stops Git Bash rewriting `/apps/...` into `C:/Program Files/Git/apps/...`.) Commit and push.

## 2. Onboard in CheatSheets

1. Create `apps/<slug>/app.json`:
   ```json
   {
     "slug": "<slug>",
     "name": "<project name>",
     "repo": "~/Projects/<repo>",
     "github": "https://github.com/DavidVeksler/<repo>",
     "commit": "",
     "built": "",
     "qa": ["check", "qa:build"],
     "drop": [],
     "runtime": ["data.json", "audio/*.mp3"]
   }
   ```
   - `qa`: npm scripts run in order. The first must build `dist/`.
   - `runtime`: globs for files the JS fetches by computed name, which the gate can't see as references.
2. Commit `app.json` alone. `sync_app.py` refuses to run while it's untracked.
3. Sync:
   ```bash
   python scripts/sync_app.py <slug> --no-commit
   ```
   On a box without a GPU browser, add `--skip-qa`, but run the QA somewhere before deploying.
4. Wire it into the site, all in the same commit:
   - `category-map.php`: `'<slug>.html' => '<Category>'`
   - `images/<slug>.png`: 1200x630. Crop a QA screenshot (the landing view usually works) with PIL, letterboxing onto the page background. Check for UI slivers at the edges.
   - Inbound links: one contextual link from the closest sheet, a sentence in the hub's `intro` in `category-hubs.json`, and an entry in `llms.txt` and `llms-full.txt` under the category (alphabetical).
   - If `build_catalog.py` puts it in the wrong shape, add `catalog-overrides.json` `{"<slug>.html": {"shape": [...]}}`.
5. Gates:
   ```bash
   for g in "scripts/build_catalog.py --check" scripts/check_hubs.py "scripts/add_hub_breadcrumbs.py --check" scripts/check_apps.py "scripts/seo_check.py <slug>.html --skip-rendered"; do python $g || break; done
   ```
6. Commit everything (the pre-commit hook rebuilds `catalog.json`) and push.

## 3. Verify locally, then deploy

1. Start the `static` preview (`.claude/launch.json` serves the repo root, the same layout as production) and open `/<slug>.html`. Check:
   - `window` ready flag or first frame;
   - no console errors;
   - every `/apps/<slug>/` resource returns 200 (`performance.getEntriesByType('resource')`);
   - lazy assets load after the first interaction (audio, say).
2. Deploy only with David's go-ahead: `bash scripts/deploy-cloudflare.sh --yes` ([`../deploy/DEPLOY.md`](../deploy/DEPLOY.md)).
3. Live check:
   - `curl -s https://cheatsheets.davidveksler.com/<slug>.html | grep -c '<distinctive string>'`
   - `curl -sI` a hashed asset should show `immutable`.
   - Or run the source repo's verify-live script.
4. Search Console: request indexing of the new URL. Note the move in both repos' `docs/seo-progress.md`.

## 4. Retire the old host (separate go-ahead)

If the project was live elsewhere:

1. Add a 301 from the old host to `https://cheatsheets.davidveksler.com/<slug>.html` as a zone Single Redirect rule.
2. Then delete the old Worker and its custom domain (or droplet vhost).
3. Remove it from `~/Projects/deploy-sites.json` and `cf-static-kit/sites.json`.

## Updating an app later

1. Commit in the source repo.
2. Run `python scripts/sync_app.py <slug>`. It builds, runs QA, copies, records the source sha in `app.json`, gates, and commits `App sync: <slug> @ <sha>`.
3. Push, then deploy with go-ahead.

Never hand-edit `<slug>.html` or `apps/<slug>/`: the next sync overwrites them.

## Gotchas

| Symptom | Cause / fix |
|---|---|
| Built HTML references `/Program Files/Git/apps/...` | Git Bash path conversion of `APP_BASE`; set `MSYS2_ENV_CONV_EXCL=APP_BASE` (sync_app.py does). |
| `check_apps`: "references nothing" | Stale file, or a runtime fetch by computed name; add a `runtime` glob. |
| `check_apps`: "outside /apps/<slug>/" | A root-absolute URL in the entry HTML; fix in the source repo. |
| Asset 404 only in production | A root-absolute `fetch` the QA didn't exercise (it runs under the base, so add a QA step that hits it). |
| `/<slug>/` 404s | Expected: the site Worker uses `html_handling: "none"`. Link `/<slug>.html`. |
| Breadcrumb gate flags the page | `add_hub_breadcrumbs.py` skips files with `apps/<stem>/app.json`; check the slug matches the filename. |
| `sync_app.py`: "build modified tracked files" | A build step rewrites a committed file (generated LUT, lockfile). Make it deterministic or untrack it. |
